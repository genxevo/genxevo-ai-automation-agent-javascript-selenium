# Architecture decision records

Each entry states the decision, the alternative that was rejected, and why. An
ADR with no rejected alternative is a note, not a decision.

## ADR-001 — `core` takes zero third-party dependencies

**Rejected:** allowing a schema library (Zod, ajv) into `core`.

A dependency-free core makes the whole security surface testable in
milliseconds and lets later siblings reuse the design. In C# the firewall would
be a project reference and in Maven a compile classpath; **npm has no
per-directory dependency scoping inside one package**, so `test/architecture.test.js`
is the only enforcement that exists. That test is therefore not optional.

## ADR-002 — the MCP low-level `Server`, not `McpServer`

**Rejected:** `McpServer.registerTool`, the ergonomic path.

Measured: it rejects a raw JSON Schema with _"inputSchema must be a Zod schema or
raw shape"_. Taking that path would mean the published result contract — the
thing this product exists to make trustworthy — is generated by Zod from a Zod
schema living in `core`, putting a third-party library's semantics and release
cadence between GenXEvo and its own contract.

## ADR-003 — GenXEvo owns output validation

**Rejected:** relying on the SDK to enforce `outputSchema`.

Measured: on the low-level path it does not. A payload missing a required field
and a payload with a value outside the published enum were both delivered to the
client untouched. `validateEnvelope()` is the net, and it reads the same frozen
schema object that is published — one artefact, two consumers, no generator.

## ADR-004 — the SDK version is pinned exactly

**Rejected:** a caret range.

Seventy-nine versions have shipped on a roughly monthly cadence. An unpinned
range is an unannounced change to a published contract. A test asserts the pin
_and_ the size of the transitive tree, so a bump is a review event.

## ADR-005 — Node floor 22.13, developed on 24

**Rejected:** floor at 24 (newest LTS) and floor at 20 (widest reach).

20 is end-of-life. 24 excludes teams still on 22, which is supported until April 2027. 22.13 is the LTS boundary where `import.meta.dirname` and
`path.matchesGlob` are both available, so the floor costs nothing in code.

## ADR-006 — modern ESM, no build step

**Rejected:** CommonJS, and TypeScript with a compile step.

The SDK is ESM-first, `import.meta.dirname` removes the `__dirname` dance, and no
build step means the published source is the audited source. JSDoc plus
`checkJs` gives editor-grade types without a compiler between the reader and the
running code.

## ADR-007 — the runtime stdout guard is primary

**Rejected:** relying on lint rules and source scans, as the Python sibling does.

Neither can see inside `node_modules`, and the SDK brings ninety-four transitive
packages into this process. The guard is installed before the SDK is loaded,
which is why every module touching the SDK is imported dynamically.

## ADR-008 — one door for every server-initiated read

**Rejected:** applying the deny-list only to agent-supplied paths.

That is the defect both siblings ship: controls built, fully unit-tested, and
wired to nothing, with discovery bypassing its own boundary. Routing discovery
through `boundedRead` gives the boundary, the deny-list and the redactor a live
production call site on day one.

## ADR-009 — `node_modules` is ignored by default _and_ read by direct path

**Rejected:** ignoring it entirely (Python's ADR-017 position).

Walking it is unbounded and useless. But `node_modules/.package-lock.json` is the
only honest answer to "what is actually installed", which is frequently not what
the project declares — and an agent that cannot tell those apart debugs the wrong
thing. So the directory is never walked and that one file is read by name.

## ADR-010 — key order is part of the contract

**Rejected:** treating JSON objects as unordered.

`JSON.stringify` emits string keys in insertion order per ECMA-262, so order is
observable to every reader of the text block. It is asserted rather than left to
luck.

## ADR-011 — real temporary directories in tests, not a filesystem fake

**Rejected:** an injected filesystem interface with one implementation.

An abstraction added because another language needed one pays no rent. The real
filesystem catches symlink resolution, junction behaviour, permission errors and
case-sensitivity — exactly the behaviours the security surface depends on. The
clock and the token source _are_ injected, because run ids and timestamps are
part of the published contract and a contract that cannot be pinned drifts.

## ADR-012 — bounded quantifiers everywhere, and an input cap

**Rejected:** a match timeout.

There isn't one. JavaScript has no regex timeout and no way to interrupt a match,
and a runaway match blocks the single event loop — so the server stops answering
everything, including the client's cancellation. This is a liveness control.

## ADR-013 — a test-name selection is a literal substring

**Rejected:** escaping metacharacters.

Escaping quietly changes what the agent asked for. Refusing tells it. Mocha's
`--grep` and Jest's `-t` are regex arguments, so an unescaped pattern is both a
selection surprise and a way to hang the runner.

## ADR-014 — a permissive-empty setting is never silent

**Rejected:** treating `deniedFileGlobs: []` as a valid quiet choice.

It is accepted, because an operator may mean it. It is warned about on every
call, because far more often someone emptied the wrong array.

## ADR-015 — the boundary's refusal is returned verbatim

**Rejected:** rewriting refusals per call site.

One error code for every path refusal in the product means an agent learns the
vocabulary once. Copied deliberately from the Python sibling, which got this
right.

## ADR-016 — no stub tools

**Rejected:** registering planned capabilities that answer "not implemented".

A stub consumes a tool slot, invites a call, and teaches the agent something
false. Planned capabilities are _published_ in `genxevo_agent_status` with their
phase, so an agent can plan around them without being able to call one.
